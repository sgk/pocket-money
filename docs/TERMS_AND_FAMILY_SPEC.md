# 利用許諾同意・親子機能 実装仕様

本ドキュメントは、利用許諾条件の同意フローと親子（保護者/子）機能の実装仕様を記録する。

## 用語
- 親: 18歳以上として同意した利用者（adult）
- 子: 招待により利用する利用者（child）
- 規約: `terms` コレクションの1ドキュメント
- 期限: 規約ごとの猶予期限（同意強制日）
- 表示開始日: 規約の表示/同意が可能となる日

## データ構造

### Firestore
#### terms コレクション
`terms/{termId}` に規約を格納する。`termId` はドキュメントIDのみを使用し、重複しないことを前提とする。

必須フィールド:
- `title` (string)
- `body` (string)
- `displayStartAt` (Timestamp)
- `graceEndsAt` (Timestamp)

#### users コレクション
親:
- `ageGroup: "adult"`
- `termsAgreement`: 親が同意した規約情報
  - `termId`
  - `agreedAt`
  - `agreedByUid`

子:
- `ageGroup: "child"`
- `parents` (親情報のリスト: `uid`, `email`, `displayName`)
- `parentUids` (親UIDのリスト)
- `parent`, `parentUid` (後方互換性のための単一親情報。順次 `parents`, `parentUids` へ移行)
- 子の `termsAgreement` は保持しない（親の同意状況は都度確認する）

#### invites コレクション
`invites/{inviteId}` に招待情報を格納する。
主なフィールド:
- `parentUid`, `parentEmail`, `parentDisplayName`
- `childEmail`
- `createdAt`
- `usedAt`, `childUid`
- `revokedAt`（取消時）

### APIレスポンス（オンボーディング）
`/api/onboarding/status` の主なフィールド:
- `state`: `ready` | `needsAge` | `needsTerms` | `needsParentConsent`
- `terms`: 表示対象の規約
- `agreedTerms`: 同意済み規約（親の場合のみ）
- `effectiveDeadline`: 現在同意済みの規約の有効期限（ISO）

## 規約の選定ルール
### 表示対象（新しい版）
1. 表示開始日が到来していない規約は除外
2. 同意済み規約と、同意済みより猶予期限が古い規約は除外
3. 残った規約のうち、猶予期限が最も将来のものを「新しい版」として提示する

### 有効期限（同意済みの失効日）
上記の「残った規約」のうち、最も早い猶予期限を同意済み規約の有効期限として扱う。

### 失効後の扱い
有効期限を過ぎたら `needsAge` として扱い、アプリの利用は不可。

## 親（adult）の挙動
- 初回ログイン時は年齢確認画面を表示
- 規約に同意すると `termsAgreement` を保存し利用開始
- 規約が追加され、表示開始日を過ぎた規約があれば「新しい版」として提示
- 規約の有効期限を過ぎると `needsAge` になり利用不可
- 同意取り消し:
  - `ageGroup` / `termsAgreement` / `parent` / `parentUid` を削除
  - 次回ログインで年齢確認画面になる

## 子（child）の挙動
- 子は自分で規約に同意しない
- 接続されている親のうち、**少なくとも1名の同意が有効であること**を、**APIアクセス毎に**確認する。
  - 1名以上の親から招待され接続されており、そのうち誰か1名でも有効な規約同意を持っていれば利用可能。
  - 規約に同意している親が一人もいなくなった場合、あるいは接続されている親がいなくなった場合は `needsAge` を返す。
  - フロントは `needsAge` を受けると自動ログアウトし、次回ログインで年齢確認画面へ誘導する。
- 親が再同意した場合、子は次回アクセスから即利用可能。
  - 子プロフィールを消さないため再招待は不要。

## 招待フロー
### 親の招待作成
- 18歳以上で同意済みの親のみ可能
- 一人の親が招待できる子は最大10名まで。
- 招待済みの子一覧と利用開始済みの有無を表示
- 利用開始済みの場合は子の名前も表示
- 招待キャンセル:
  - 利用開始済み: 子の利用権が失われる旨を確認表示
  - 未開始: 追加の注意は表示しない
  - キャンセル成功時、フロントエンドは `bootstrap` 情報を再取得し、ユーザーメニュー等の表示を即座に更新する。

### 子の招待受理
- 子は親のGoogleアカウントを入力。
- 接続先の親が有効な同意を持っている場合のみ受理。
- 子プロフィールに `ageGroup=child` を設定し、`parents` / `parentUids` リストに親情報を追加する。
- 最大10名までの親と接続可能。
- 子の `termsAgreement` は保存しない。
- 親が子のデータ表示（`X-Child-Id`）中に子設定画面から「招待を確認する」を実行した場合、対象はログイン中の親本人ではなく `X-Child-Id` の子とする。
  - つまり、親Aが子Bを表示中に親Cを入力した場合は `C→B` の招待を確認する。
  - `C→A` の招待は確認しない。
  - この操作は、`X-Child-Id` の子に接続済みの親のみ実行できる。

## UI仕様（抜粋）
- 子の設定画面に「利用許諾条件」「危険な操作」は表示しない
- 子が `settings/terms` を直接開いても表示されない（設定へリダイレクト）
- 規約ページ
  - 新しい版がある場合のみ表示して同意を促す
  - 同意済み規約を表示し、必要なら「無効になる日」メッセージを表示
  - 「同意をとりやめる」ボタンで即ログアウト
- 年齢確認画面
  - 子の場合、親のアカウント入力欄のそばに規約の表示開始日/猶予期限は出さない

## 例外・エラー
- 親の同意が無効な場合、招待受理は 403 で拒否
- `needsAge` 状態で API にアクセスすると 403 を返し、フロントはログアウト

## 親子共有機能（親による子のデータ表示）

### 概要
親ユーザーは、自身が招待した子ユーザーのアカウントとしてログインしているかのようにデータを閲覧・編集できる（なりすまし表示）。

### 実装メカニズム
1. **コンテキストの保持**:
   - フロントエンドの `AuthContext` で `childId` を保持する。
   - 子ユーザーを選択すると、`childId` が `localStorage` に保存され、API リクエストの `X-Child-Id` ヘッダーに付与される。
2. **バックエンドの処理**:
   - `get_ready_user` 依存関係が `X-Child-Id` ヘッダーを検出し、親子の正当性を確認。
   - 正当な場合、API の実行コンテキスト（`request.state.user`）を子ユーザーの UID に切り替える。
   - レスポンスに `Vary: X-Child-Id` ヘッダーを付与し、キャッシュの衝突を防ぐ。
   - `/api/onboarding/accept-invite` も `X-Child-Id` を解釈し、招待確認対象を子ユーザーに切り替える。
3. **フロントエンドのキャッシュ分離**:
   - TanStack Query の `queryKey` に `childId` を含めることで、親と子それぞれのデータを独立して保持する。
   - コンテキスト切り替え時に `useInvalidateLedger` を呼び出し、古いデータのキャッシュを無効化・再取得する。

### UI/UX の挙動
- **ユーザーメニュー**: 親のメニューに「データの切り替え」セクションが表示され、各子の名前を選択できる。
- **リダイレクト**: 子コンテキストに切り替えた際、現在表示中の資産（いれもの）が子のアカウントに存在しない場合は、自動的にダッシュボード（まとめ）へリダイレクトする。
- **表示制限の動的変更**:
   - **親が自分を表示**: すべての機能（設定、招待、危険な操作、利用許諾）が利用可能。
- **親が子を表示**: 設定、危険な操作（データ削除等）は利用可能。利用許諾セクションは非表示。
   - **子が自分を表示**: 設定、学年設定のみ利用可能。招待、危険な操作、利用許諾セクションは非表示。
- **学年設定**: 親が子の学年を変更した場合、その変更は即座にサーバーに保存され、親の UI にも反映される。バックグラウンドのリフェッチによる学年の「揺り戻し」を防ぐため、UI 側で同期状態を管理する。
